# 输出契约

## 客户可见内容

### 一封信

一个具体且适合展示的事实开头；中段如实解释钱的变化，连接客户确认的生活；结尾保留选择。默认450–700字，可按资料量缩短。演示稿在标题和正文外同时保留“虚构示例”标记。署名默认“且慢”，不要代署林杰才、Iris、E大或未确认的顾问。

### 财富档案

依次呈现：
1. 版本、截至日期、范围；
2. 资产与资金变化摘要，损益与投入分开；
3. 已确认资金用途和仍未知的部分；
4. NEED／WANT／DREAM三层目标，仅放已确认或本人待填写的项目；
5. 至多3条个人发现，每条含事实、解释、条件、可选下一步；
6. 一件可由本人确认的后续安排与可选复核日期；
7. 纠错入口或待补充问题。

### 财富记忆

1–3个时刻，每个含时间、事件、一段克制的原创说明。本人原话需标明来自该客户；没有原话则保留一个可编辑问题。资料不足时生成待填页，而不是强行生成时间轴。

## 结构化草稿

输出JSON示意：
```json
{
  "customer_id":"demo-001",
  "as_of":"2026-11-20",
  "status":"draft",
  "synthetic":true,
  "letter":{"title":"留给这一段时间的你","paragraphs":[{"text":"...","evidence_ids":["F01"]}]},
  "dossier":{"title":"我的财富档案","sections":[{"label":"...","text":"...","evidence_ids":["F01"]}]},
  "memories":[{"date":"2026-09-18","title":"...","text":"...","evidence_ids":["F06"],"editable_prompt":"你愿意为这一页留下什么？"}],
  "editorial_notes":{"missing":[],"reviews":[]}
}
```

段落没有事实主张时可留空证据数组；不得让空数组包裹未经举证的数字、心理判断或人生事件。客户版隐藏这些内部编号。证据覆盖检查不是语义审查的替代。

## 交付与升级

默认只交付草稿。若要真实产品批量使用，先接可信事实与授权，再做逐客校验、人工抽检及客户样本试读。用户未授权触达时不向任何客户发送。

评估两组结果：内部稿件质量与客户实际反应。建议先覆盖6种状态做匿名试读；记录“不像我”“过度知道我”“愿意保存”“希望删除”的理由。不得编造客户好评或用阅读完成率证明被理解。
